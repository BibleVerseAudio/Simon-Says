# Simona Says — Judges' Technical Report (ASD-STE 100)

## 1. Purpose

This document describes the Simona Says project. It explains the game design, the SAM outline control, the configuration methods, and the construction methods. The purpose of this app is a game that can also second as a exercise app, you can sit down and play it for easy mode or go full body and floor routine in boot mode and hard mode.

## 2. The Project in Brief

Simona Says is a mobile game for the Meta Muse Hackathon. The player listens to audio commands. The player stands in front of the telephone camera. The player does the body actions. The game checks the body actions. The game gives a result.

The game has five modes. Easy mode uses a female voice and upper-body commands. Hard mode uses a male voice and full-body commands. VS mode uses a challenger. Bootcamp mode uses floor and cardio commands. Kids mode uses slow, friendly commands and no trick commands.

The game also calculates calories. The game saves stars. The game shows a progress graph over seven days.

## 3. The Core Idea

The core idea is simple. The team does not use a pose model. The team does not use skeleton joints. The team uses the SAM 3.1 segmentation box as the game controller. The box gives position and size. The game measures change in position and size. The game decides if the change is correct.

SAM is an any-movement segmenter. SAM is not an action recogniser. SAM gives a person box for each frame. The game converts the box to movement evidence. The game does not ask SAM for action names.

## 4. System Build

The game uses React Native 0.81 with the React Native CLI. The programming language is TypeScript. The camera library is react-native-vision-camera 4.7.3. The audio library is react-native-sound. The storage library is AsyncStorage. The test tool is Jest. The device is Android. The telephone is the test target.

The camera uses the front lens. The camera shows a selfie view. Easy mode and Kids mode zoom to 1.4 times. Hard mode and Bootcamp mode zoom to 0.6 times. The game does not use frame processors. The team removed the frame processor because the worklets library caused duplicate native module errors on Android.

## 5. The SAM Outline Control

### 5.1 How SAM Works in This Game

The game sends a snapshot to the Meta Model API. The API model is sam-3.1. The request uses the Responses API over HTTPS POST. The input is the text "person" and a JPEG image. The image is small. The maximum side is 320 pixels. The quality is 70 percent. The API returns boxes in a text format. The game parses the boxes. Each box has x1, y1, x2, y2, width, height, and confidence.

The key is stored on the device. The key is not sent to the judges. The key is not shown in full in the application. The Settings screen saves the key. The Settings screen shows only the last four characters.

### 5.2 The Baseline

The game makes a baseline before play. The baseline is the resting box of the player. The game takes many samples. The game uses the median of the samples. The game accepts the median only if two or more samples agree. One frame alone does not make a baseline. A moving frame does not become the baseline.

### 5.3 The Verdicts

The game uses three verdicts. The verdicts are in src/sam/verifier.ts.

- PASS: the movement matches the command.
- FAIL_MOVE: the movement is wrong. The player moved on a trap command. The player did not move on a Simon command.
- UNVERIFIED: the camera or the network did not give evidence. The game pauses. The game does not give a loss for UNVERIFIED.

### 5.4 How the Game Judges Movement

The judge measures two values. The first value is grow. Grow is the change in box area. The second value is shift. Shift is the change in box centre. Each command class has a threshold. A big command has a high threshold. A small command has a low threshold. Kids mode uses one quarter of the threshold.

The judge also measures jerk. Jerk is irregular movement in the box path. The game uses the centroid path from the burst frames. A jerky movement fails. A smooth movement passes. The first FAIL_MOVE ends the adult run. This is sudden-death. Kids mode makes three tries. Kids mode does not give a loss.

### 5.5 The Signature Engine

The team made a signature engine in src/sam/signatures.ts. One box becomes nine numbers. The numbers are centre x, centre y, area, aspect, top, bottom, left, right, and height. The engine compares the numbers before and after the command. The engine gives a sign.

The signs are STILL, RAISE_UP, CROUCH_DOWN, JUMP_UP, STEP_LEFT, STEP_RIGHT, STEP_FORWARD, STEP_BACKWARD, WIDEN, NARROW, LEAN_LEFT, LEAN_RIGHT, SPIN, and UNKNOWN.

The order of the checks is important. STILL is first. RAISE_UP is second. CROUCH_DOWN is checked before WIDEN because a squat also makes the box wide. SPIN uses a narrow aspect. Steps use the centre. Leans use a small centre change.

Each command maps to one or more signs. Raise hands maps to RAISE_UP. Cross arms maps to NARROW. Jump maps to JUMP_UP. Squat maps to CROUCH_DOWN. Spin maps to SPIN. Steps map to STEP_LEFT and STEP_RIGHT.

The screen shows the box and the sign. The judges see the SAM outline in real time. The outline is green. The sign text is on the outline.

### 5.6 Sampling for Cost Control

The game does not call SAM for every command at high stages. At stage 4 and above, the game samples one in two commands. At stage 7 and above, the game samples one in three commands. The other commands pass on the honor tick. The log records the sampled commands. The team states this honestly.

## 6. How the Team Configured SAM for This Game

### 6.1 Framing

The game gates play on framing. The player must stand in the correct frame position. Easy mode needs the face and shoulders big in frame. The box area must be between 18 percent and 90 percent. Hard mode needs the full body. The box area must be between 12 percent and 60 percent. Bootcamp needs the full body and floor. The box centre must be low in the frame.

The camera zoom matches the mode. Easy mode uses 1.4 times zoom. Hard mode uses 0.6 times zoom. The player sees a framing message. The game does not start the countdown before the framing is correct.

### 6.2 Guided Body Setup

The team added a guided body setup. The setup is in src/sam/calibration.ts. The setup has steps. The player holds each pose. The system takes one SAM mark per step.

The adult steps are stand still, touch right ear, touch left ear, raise hands, touch head, cross arms, crouch, step right, step left, and stand still. The kids set is short. The kids set has five steps.

Each step shows cyan zone marks. The zones are box-geometry approximations. The zones are not skeleton joints. The team states this honestly. The left and right mapping uses the touch steps. The front camera mirrors the image. The setup records if image left is player right.

### 6.3 Personal Profile

The setup makes a personal profile. The profile is stored on the device. The profile has the resting box, neutral area, neutral aspect, neutral centre, zone rectangles, and movement deltas. The deltas are arms-up delta, crouch delta, and step delta.

The profile gives a threshold scale. The scale is in the function thresholdScale. A small mover has a small delta. The game uses a low scale for a small mover. A big mover has a scale near one. The scale is between 0.5 and 1.25. Low confidence limits the scale. The judge uses the scale in expectationFor. The game shows the scale on the screen as a percent.

### 6.4 Countdown Gate

The game uses a 10-second countdown. The countdown starts only after the profile is ready. The countdown is not blind. During the countdown the game takes more samples. The samples refine the baseline. The median method is used again. Play starts when the countdown ends.

The player can skip the setup. The skip uses default thresholds. The skip is shown on the screen. The skip does not give a loss.

### 6.5 Video Strip and Grid Tiebreak

The game takes burst frames during each command. The burst frames are at 40 percent and 80 percent of the audio time. The frames are tag-marked by command. Old frames do not enter the next command.

The game builds a video strip from the burst frames. The strip is the centroid path. The game calculates path length and hold score. The game also makes a grid profile. The grid is 6 columns by 8 rows. The game compares grid profiles. The grid delta is a tiebreak.

A pass with a flat hold on a move command gives UNVERIFIED. The game does not give a free pass. The game does not give a loss.

## 7. Safety Rules

The game separates proven faults from service faults. A network error is UNVERIFIED. A missing key is UNVERIFIED. No silhouette is UNVERIFIED. UNVERIFIED pauses the game. The player taps resume. Only FAIL_MOVE ends the run.

The team does not give points on SAM failure. Kids mode gives three tries. Kids mode keeps the star on SAM failure.

Async safety is used. Each run has a run identifier. Each command has a sequence number. Burst frames carry the sequence number. Slow answers after retry are dropped. The timer is pure. No state update is inside an updater.

## 8. The Game Modes in Detail

### 8.1 Easy Mode

Easy mode uses the female voice. Easy mode has 20 upper-body commands. The camera zooms to 1.4 times. The framing needs the face and shoulders big in frame.

### 8.2 Hard Mode

Hard mode uses the male voice. Hard mode has 40 commands. The commands are 20 upper-body and 20 lower-body. The camera zooms to 0.6 times. The framing needs the full body.

### 8.3 Bootcamp Mode

Bootcamp mode uses the male voice. Bootcamp mode has 12 floor and cardio commands. The commands are lie on back, sit-up, push-up position, push-up, plank, jumping jacks, burpee, mountain climbers, sit and stand, lie and jump, kneel, and stand tall. The player can pick a round length. The lengths are 30 seconds to 10 minutes.

### 8.4 Kids Mode

Kids mode uses the female voice. Kids mode has eight friendly commands. Kids mode has no trick commands. Kids mode always uses the Simon prefix. Kids mode uses three tries. Kids mode has no YOU LOSE screen. The speed follows the success rate.

### 8.5 VS Mode and Online

VS mode uses a lobby. The player picks Easy, Hard, or Bootcamp. The online screen is a 2 by 2 grid. One cell is the player. Three cells are bots. The game is a simulation. The team states this honestly. The VS mode uses stars. The winner gets one star. The losers lose one star. The floor is zero.

Friend duels use a six-character code. The code is shared with the Share function. The code expires after seven days.

## 9. Stages and Difficulty

The game has ten stages. The stages set speed, gap, and trick rate. Stage 1 uses 0.85 times speed and 20 percent tricks in hard mode. Stage 10 uses 2.5 times speed and 70 percent tricks. The timer does not end the run. The timer moves to the next stage. The run ends only on FAIL_MOVE.

Elite players get a bonus. The hit rate must be 80 percent or more over eight tries. The speed increases by streak. The gap has a floor of 0.35 seconds. The trick rate is 65 percent for elite players.

Kids mode uses adaptive speed. The speed moves to a target. The target is based on hit rate. The speed is between 0.7 times and 1.5 times.

Commands are drawn without immediate repeats. The game uses a no-repeat history. Adults use a history of five. Kids use a history of three.

## 10. Fitness and Calories

The game counts calories. The model uses the MET method. The weight is 70 kilograms. Light arm moves use 3.0 MET. Jump and spin moves use 8.0 MET. Plank uses 5.0 MET. The calories count only on proven moves. The screen shows the calories in the corner. The screen shows the calories on the lose card.

## 11. The Muse Spark Coach

The game uses Muse Spark 1.3. The model is muse-spark-1.3. Spark gives advice only. Spark does not give verdicts. Spark does not replace SAM.

The game sends only game statistics. The game does not send images. The game does not send audio. The game does not send personal data. The statistics are score, hits, tries, streak, stage, speed, and failure reason.

Spark replies with JSON. The fields are next stage delta, trick rate, feedback, and recalibrate flag. The game validates the JSON. The stage delta is minus one, zero, or one. The stage delta applies only at the timer boundary. The trick nudge is small. The nudge is between minus 0.1 and plus 0.1. One accessor gives the trick rate. All command draws use the accessor.

The game calls Spark every fourth verdict in adult modes. Kids mode does not call Spark. Kids mode uses local template tips. The end-of-run summary reuses the last tip. The game does not pay for a second call.

Spark replies are run-guarded. Slow replies after retry are dropped. The screen shows the source. The source is live, no-key, timeout, offline, parse, or local. The screen shows the latency in milliseconds. The screen shows the time.

If Spark says recalibrate, the game acts. The lose card shows a redo body setup button. The button opens the guided setup. The signal is not only a hint.

The Settings screen has a Test Spark 1.3 live button. The button runs a smoke test. The test shows the model, the latency, the source, and the feedback. The judges must record the live output before the demo. Mock tests do not prove the live model. The team states this honestly.

## 12. Content Production Methods

### 12.1 Audio

The team made the command audio with edge-tts. The female voice is en-US-AriaNeural. The male voice is en-US-ChristopherNeural. The rate is minus 10 percent. The volume is plus 20 percent. The pitch is minus 15 Hz. Each command has a plain file and a Simon file. The files are in Android raw resources. The names use the voice prefix. Example: female_simon_raise_both_hands.mp3.

The command set has 20 upper-body commands. Hard mode adds 20 lower-body commands. Bootcamp adds 12 floor commands. The total audio set is large. The game uses the files from the device. The game does not download the files during play.

### 12.2 Artwork

Muse Image made the artwork. The files are simona.png, easy.png, and hard.png. The home screen uses a poster. The poster says SIMON SAYS at the top. The poster says PICK YOUR MODE at the bottom. The image is not cut.

### 12.3 Build and Push Methods

The build is Gradle 8.14.3. The debug build gives app-debug.apk. The build uses the debug keystore. The push uses Android Debug Bridge (adb). The install uses adb install -r. Metro serves the debug JavaScript. The device reverse uses adb reverse tcp:8081 tcp:8081.

The team fixed an invariant error. The native main component name did not match the JavaScript name. The name was fixed to SimonaSays. The team fixed a camera error. The permission request was missing. The game now requests the camera permission on open. The game shows an allow button if the permission is blocked.

## 13. Test Methods

The team uses Jest tests. The tests do not use the camera. The tests do not use the network. The tests use mocks for fetch.

The verifier tests check six rules. The signature tests check four rules. The calibration tests check five rules. The Wonder tests check three rules. The Spark tests check eight rules. The total is 26 tests. The last run gives 26 passes.

The tests check valid Spark JSON. The tests check malformed JSON. The tests check HTTP 401. The tests check no key. The tests check the smoke gate. The tests check abort as timeout. The tests check posture clamping. The tests check kids tips.

TypeScript compiles with no errors. The command is npx tsc --noEmit. The build passes with assembleDebug.

## 14. Honesty for the Judges

The SAM zones are not joints. The SAM boxes are not skeleton data. The silhouette grid is an approximation. The grid uses the box and a vertical mass model. The grid is not a pixel mask.

The online VS mode is a simulation. The bots use random numbers. The team does not claim real online SAM duels at this stage. The duel codes are local.

Muse Spark is advice only. Spark does not judge moves. Spark does not give the win. SAM gives the verdicts.

The debug battery uses Metro. The release build must be used for a standalone demo. The debug APK needs the Metro server for code changes.

## 15. Privacy

The API key stays on the device. The key is shown with a mask. Only the last four characters are visible. Spark sends only aggregate statistics. SAM sends only small JPEG images of the player frame. The game does not store the images. The game stores the calibration profile and the history on the device.

## 16. Conclusion

The team made a game where the SAM box is the controller. The game uses framing, calibration, and a personal threshold scale to make the box fair for each player. The game uses signatures, jerk measurement, and a video strip to make the verdict strong. The game uses fail-safe rules to separate service faults from player faults. The game uses Muse Spark as a coach, not a referee. The methods are in the code and the tests. The judges can verify the code and the tests.
